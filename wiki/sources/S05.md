# S05 · Asai 等人的 Self-RAG 論文

## 原始資料

本頁引用 2023-10-17 提交的 [arXiv v1](https://arxiv.org/abs/2310.11511v1)，於 2026-11-22 從 [arXiv 全文 PDF](https://arxiv.org/pdf/2310.11511v1) 取得。本機保存的原件共 30 頁。來源版本 ID 見[清冊](../source-catalog.md)，頁碼依本機 PDF。

## 摘要與適用條件

作者研究如何讓模型依任務和生成進度檢索，並利用自己預測的標記評估證據與續寫。[S05，§3.1–3.2，頁 3–5](#evidence-01) [S05，§3.3，頁 6](#evidence-04) 實驗採用 Llama 2 7B／13B，涵蓋封閉選項、短答與長文生成。評估指標和檢索設定依任務而異。[S05，§4.1–4.3，頁 6–7](#evidence-05)

## 證據定位

<a id="evidence-01"></a>

- **S05，§3.1–3.2，頁 3–5，表 1 與圖 2**：訓練時以評論模型離線標記資料，讓生成模型學會預測正文與反思標記。推論時生成模型自行產生標記，檢索仍由檢索器執行。表 1 的四類標記為 `Retrieve`、`IsRel`、`IsSup`、`IsUse`。

<a id="evidence-02"></a>

- **S05，§3.1 與演算法 1，頁 3–4**：模型根據輸入及先前生成文字預測 `Retrieve`。需要檢索時找候選段落，分別以各段落生成續寫；不需檢索時直接繼續生成。論文實驗以句子作為生成段的單位。

<a id="evidence-03"></a>

- **S05，§3.3，頁 6；附錄 A.3，頁 19**：可直接依模型預測的 `Retrieve` 標記觸發。也可使用門檻，A.3 的軟式判定以 `P(Yes) / (P(Yes) + P(No))` 超過設定值才觸發檢索。

<a id="evidence-04"></a>

- **S05，§3.1 表 1、§3.3 式 3–4，頁 4、6**：`IsRel` 判斷段落是否與輸入相關，`IsSup` 判斷續寫是否獲段落支持，`IsUse` 估計回答對輸入的效用。取回多段時，模型分別生成候選，用生成機率與加權的評論分數做分段束搜尋。論文也提出依標記過濾候選的硬式控制。

<a id="evidence-05"></a>

- **S05，§4.1–4.3、§5.1 表 2，頁 6–8**：在 ASQA 的指定文件設定下，Self-RAG 13B 的引用 precision／recall 為 70.3／71.3，Ret-ChatGPT 為 65.1／76.6。兩項指標呈現不同結果；數值對應此任務與設定。論文的標準 RAG 基線先取回文件，再把文件放在查詢前提供給生成模型。

<a id="evidence-06"></a>

- **S05，附錄 C.2、表 6，頁 21、24**：作者列出模型將不相關的段落誤判為相關且支持回答的案例。反思標記是模型預測，可能出錯。
